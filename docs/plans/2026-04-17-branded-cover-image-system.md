# Branded Cover Image System

**Date:** 2026-04-17
**Status:** Design approved → ready for implementation plan
**Owner:** Ali Sadikin
**Related:** [Auto-Pipeline + Trending Cron](./2026-04-17-auto-pipeline-and-trending-cron.md) (cover branding applies to both manual and auto pipelines)

## Context

Current cover images generated by the Content Engine are beautiful but **off-brand**:
- No post title overlay (covers look like stock photography, not personal thumbnails)
- When covers depict humans, they're random/generic — no consistent creator presence
- Default model `nano-banana-2` — lower text-rendering quality than available `nano-banana-pro`

Goal: turn covers into on-brand thumbnails that (1) always display the post title as overlay text, (2) always feature Ali's face when the cover involves humans, (3) use the best available model for text-in-image rendering.

## Design

### Decisions Locked (from brainstorm)

| Area | Choice | Why |
|------|--------|-----|
| Title rendering | Prompt-injected instruction (NB Pro text-in-image) | NB Pro unggul di legible text. Simpler than canvas overlay. Embedded in image = good for social-share og:image. |
| Face auto-inject trigger | Regex keyword scan of Visual Direction + prompt_text | No LLM call (fast, free). ~20 English+Indonesian terms. Covers 90% of cases. False positives acceptable (NB Pro ignores irrelevant refs). |
| Creator face storage | Reuse existing `profile_photo` in About Settings | No new upload UI. User already manages this field. Tradeoff accepted: same image used for hero + AI ref. |
| Scope | Cover images only | YAGNI — inline images usually conceptual/diagrammatic, don't need creator presence. Explicit user spec. |
| Default model | `nano-banana-pro` (global default) | User request. Cover type forces NB Pro regardless (text rendering requirement). |
| Enhancement timing | Dispatch-time in `ImageGenerationService::triggerForIdea` | DB prompts stay "raw" → reproducible regen. Clean separation (authoring = creative, dispatch = mechanical enhancement). Easy kill-switch. |

```

NEW: CoverBrandingEnhancer injected into ImageGenerationService

  ┌────────────────────────────────────────────────────────────┐
  │  enhancer.enhance(prompt, idea):                           │
  │                                                            │
  │  if prompt.type != 'cover'  → pass-through (no change)     │
  │                                                            │
  │  if prompt.type == 'cover':                                │
  │    1. Inject title instruction:                            │
  │       append 'Add large bold thumbnail-style title "{T}"…' │

  │    2. Scan VD+prompt for human keywords (regex):           │
  │       if match:                                            │
  │         url = getCreatorFaceUrl()  (Setting: profile_photo)│
  │         if url: face_refs = [url, ...existing]             │
  │    3. Force model = 'nano-banana-pro'                      │
  │                                                            │
  │  return enhanced_prompt                                    │
  └────────────────────────────────────────────────────────────┘
       │

  ImageGenerationService::queue(
     $postId, $finalPrompt, $type,
     $model = enhanced,              ← NB Pro forced for cover

     $styleRefs, $additionalNotes
  )
       │
       ▼
  GeminiGen multipart POST → webhook callback → image stored → applied to post
```

### Feature Details

**A. Title Overlay Instruction Template**

Appended to cover prompt string:
```
. Add large bold thumbnail-style title text "{{post_title}}" overlaid in
the upper-left third of the frame. Use clean sans-serif typography in
white with a subtle dark drop shadow for high contrast against the
background. Styled like a premium YouTube thumbnail — text must be
clearly legible and not obscure focal subjects. Do not stretch, distort,
or duplicate the text.
```

- **Title source:** `idea.generated_article[primary_lang].title` → fall back to `idea.generated_article.title` → fall back to `idea.title`
- **Truncation:** ≥70 chars → truncate to 67 + `...` for overlay instruction only (doesn't touch post.title)
- **Sanitization:** strip emoji (NB Pro renders them unreliably), escape `"` → `'`, JSON-safe

**B. Human Keyword Regex**

Case-insensitive, word-boundary matching on `visual_direction + ' ' + prompt_text`:
```
\b(person|people|man|woman|face|portrait|human|creator|founder|speaker|author|selfie|figure|pria|wanita|orang|manusia|muka|wajah|pembicara|tokoh|penulis|pencipta)\b
```

Intentionally excluded: `hands` (too common in "hands-on tutorial"), `user` (too generic), `developer/engineer` (often abstract).

**C. Creator Face URL Resolution**

```php
$setting = Setting::where('group', 'about')->where('key', 'profile_photo')->value('value');
if (!$setting) return null;
$path = str_starts_with($setting, 'http') ? $setting : url('/storage/' . ltrim($setting, '/'));
// Verify file actually exists on disk for local paths
if (!str_starts_with($path, 'http') && !Storage::disk('public')->exists($setting)) return null;
return $path;
```

Safety: if URL empty or file missing → log warning + return null → face inject skipped (cover still generates with title overlay, just no creator).

**D. Model Override Logic**

```php
$finalModel = match(true) {
    $prompt['type'] === 'cover' => config('content.cover_branding.model', 'nano-banana-pro'),
    !empty($prompt['model']) => $prompt['model'],
    default => config('content.default_image_model', 'nano-banana-pro'),
};
```

Covers FORCE NB Pro. Non-cover respects user's per-segment model choice or falls back to global default (also now NB Pro).

**E. Frontend Default Change**

`ImageConfigModal.vue:21`:
```js
const selectedModel = ref('nano-banana-pro')  // was 'nano-banana-2'
```

`modelOptions` reordered to `['nano-banana-pro', 'nano-banana-2', 'imagen-4']` so dropdown opens with Pro first.

### Edge Cases

1. `profile_photo` not uploaded → log warning, skip face inject, still generate cover with title
2. Title has quotes → escape `"` → `'`
3. Title has emoji → strip (NB Pro unreliable with emoji)
4. Title > 70 chars → truncate overlay instruction to 67 + ellipsis (post.title unaffected)
5. User manually uploaded face_refs in ImageConfigModal → creator_face appended AFTER user refs (user refs have priority in GeminiGen attention)
6. Keyword false positive (e.g. "people who code" in abstract laptop cover) → acceptable; NB Pro ignores irrelevant face_ref
7. Indonesian prompt → regex includes ID keywords (orang, manusia, muka, wajah, pembicara, tokoh, penulis, pencipta, pria, wanita)
8. Regenerate cover → enhancer runs fresh each time, reproducible
9. Non-cover prompts (inline) → 100% pass-through, zero change
10. `COVER_BRANDING_ENABLED=false` → enhancer short-circuits at entry, returns prompt unchanged

### Out of Scope (NOT building)

- ❌ OCR-based title render validation
- ❌ Canvas/Intervention post-processing fallback
- ❌ Inline image face injection
- ❌ Multi-face library (single profile_photo only)
- ❌ Per-pillar title styling variants
- ❌ Admin UI for managing keyword list (hardcoded in service for now)
- ❌ Localized title overlay (title always rendered in its original language)
